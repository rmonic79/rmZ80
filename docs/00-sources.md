# 00 — Sources: provenance and classification

Where every fact in this core comes from. In a clean-room project this is not
paperwork: it is the record that shows the RTL was written from admissible
sources. Every other document in `docs/` cites its sources inline with the tags
defined here.

The documents themselves are third-party copyrighted material and are not in this
repository: [UM] and [PS] are published by Zilog (documents UM0080 and PS0178), [SY]
by its author.

## Documents

| Tag | Document | Class |
|---|---|---|
| **[UM]** | Zilog, *Z80 CPU User Manual*, UM008011-0816. The primary source: register model, instruction set, M-cycle and T-state tables, interrupts, bus timing | manufacturer documentation |
| **[PS]** | Zilog, *Z80 CPU Product Specification*, PS0178. Pin timing diagrams, including bus request/acknowledge (figure 10) | manufacturer documentation |
| **[SY]** | Sean Young, *The Undocumented Z80 Documented*, version 0.91 (2005). Undocumented flags (bits 5 and 3 of F), opcodes on the halves of IX/IY, the unassigned `ED` and `DD`/`FD` positions, `DAA` over its whole input space, interrupt details | third-party description of measurements on real hardware, with declared provenance; not code |

Page numbers: [UM] pages are the manual's printed page numbers (PDF page = printed
page + 14). [SY] pages are the PDF's own.

**Rule for [SY].** It is not manufacturer documentation, so it is used where [UM]
is silent and every fact taken from it is marked `[SY]` in the documents. It was
checked for reliability where both sources speak: on `DAA` (684 input
combinations covered by [UM]), on the `EI` delay and on the durations of the three
interrupt modes it agrees with [UM] everywhere (`05-alu-and-flags.md` §8.3,
`04-interrupts.md` §3–§4). Where the two disagree, the document says so and
states which one the core follows and why (`04-interrupts.md` §6, `RETI`).

## Test programs and test vectors

These run on the CPU, or describe expected CPU behaviour, and are used to check the
core. They are not compiled into the design. No RTL is derived from z80test or zexdoc;
SingleStepTests are also the reference for what no document fixes, as data only (below).

| Name | What it is | Where the expected values come from | Licence | In this repository |
|---|---|---|---|---|
| **z80test** 1.2a (Patrik Rak) | `z80full`, `z80doc`, `z80flags`, `z80docflags`, `z80ccf`, `z80memptr`: every instruction run over many operand values, a CRC of registers and flags compared with a stored value | a real ZX Spectrum with a Zilog Z80 | MIT | yes, the release binaries, in `sim/z80test/` |
| **SingleStepTests** z80 v1 | 1000 cases for each of 1604 opcode positions (all but the 12 prefix bytes and 176 of the 178 `ED` positions that act as two NOPs, all but `ED 77` and `ED 7F`): initial state, final state (registers, `WZ`, memory) and the bus cycles, one entry per T-state | generated by a software model of the Z80 (per its README, derived from an existing emulator, with corrections) | MIT | no, 1.3 GB: `sim/get_sst.sh` downloads it |
| **zexdoc** (Frank Cringle) | CP/M program exercising the documented instruction set, CRC of registers and documented flags | a real Z80 | GPL-2 | no: run locally, result reported in `STATUS.md` |

SingleStepTests are the output of a model, not of silicon. They are the
reference for what no admissible document fixes (chiefly the per-instruction rules
of the internal register `WZ`, `01-registers-and-state.md` §7); z80test, whose
values come from silicon, observes those same rules through `BIT n,(HL)`
(`z80memptr`) and through bits 5 and 3 of F (`z80full`), and passes.

## Not used

- **Source code of any existing Z80 core or emulator**, under any licence. Not
  copied, not paraphrased, not recalled.
- Opcode maps, wikis and tables by third parties without traceable provenance
  (opcode reference sites, "decoding Z80 opcodes" pages): the problem is not their
  quality but that a claim without provenance cannot be checked.
- Binaries of any system used as a behavioural reference.
